# 22 周总计划

## 成功定义

22 周后不是“看过微服务和 RAG”，而是能够：

- 独立完成六个 Java 微服务的开发、测试、部署和排障。
- 解释文档摄取、混合检索、RAG 编排、流式输出、模型降级和租户隔离。
- 用性能、故障和评测数据证明项目质量。
- 在无提示情况下完成深圳初级 Java 后端岗位的项目追问和基础面试。
- 已开始外部求职，具备稳定的深圳岗位管道。

## 阶段划分

### 阶段一：Java 与工程基础（W1–W4）

补足 Java、SQL、Spring Boot、测试和 Docker。进入 W5 前必须能独立写出带参数校验、统一异常、MySQL 持久化、数据库迁移和集成测试的 REST 服务。

### 阶段二：微服务骨架与异步摄取（W5–W8）

建立六服务仓库、Nacos 注册、Gateway 路由、认证与 Workspace 隔离、MinIO 文件存储、RabbitMQ 异步任务，以及文档解析与分块。

### 阶段三：RAG 主链路（W9–W12）

接入 Spring AI 和国内模型 API，完成 Qdrant 混合检索、RAG Advisor、SSE 流式回答、引用、会话记忆、多租户过滤和 Prompt 版本。

### 阶段四：可靠性、评测与部署（W13–W15）

完成 Sentinel 限流熔断、Ollama 降级、可观测性、黄金问答评测、GitHub Actions、2C4G 部署和 HTTPS。

### 阶段五：求职、压测和面试（W16–W22）

完成聊天控制台、故障报告、性能报告、架构文档和演示视频；开始外部投递，并同步进行算法、计算机基础、项目追问和模拟面试。

## 不可妥协项

- 算法每周持续推进，不因项目延期取消。
- 每个核心场景至少有自动化测试。
- Workspace 数据隔离必须在数据库、检索和缓存三处验证。
- 模型 Key 不进入代码和 Git 历史。
- 没有书面 offer 不离职、不搬迁。
- 项目必须公网可访问，不能只展示截图。

## 降载规则

- 落后不足一周：使用每周弹性晚补齐，不无限顺延。
- 落后一至两周：先移除管理台高级筛选、额外 Prompt 模板和可选 Reranker。
- 落后超过两周：保留六服务主干、摄取、检索、聊天、租户隔离、模型降级、评测和部署；把算法新题从 100 道降到 80 道，但保留二刷。
- 无论何种降载，不删除测试、部署和面试表达。
