# 深圳外部求职执行

## 原则

- 只考虑外部岗位，不把内部转岗作为备选。
- 先线上面试，拿到书面 offer 后再辞职和搬迁。
- 简历只写真实完成的项目，不虚构开发工龄。
- 第一份开发工作优先自研，外包和驻场作为兜底。

## 岗位分层

### A 档

AI 应用平台、企业知识库、RAG 平台、成长型 B 端 SaaS 的 Java 后端岗位。

### B 档

普通自研团队、中小型互联网、企业软件和业务中台岗位。

### C 档

外包、驻场、乙方交付和开发支持岗位。用于缩短第一份开发工作的等待时间，不放弃后续跳槽。

## 时间线

| 周次 | 动作 |
| --- | --- |
| W10 | 建立 40 家深圳公司清单，不投递 |
| W16 | 每周试投 5–8 个 B/C 档岗位 |
| W18 | 扩至每周 15–20 个 A/B/C 档岗位 |
| W19–W22 | 保持投递，复盘反馈，准备现场终面 |

## 跟进字段

使用 [tracker.csv](tracker.csv) 记录：

- 公司、岗位、城市、渠道和链接。
- 岗位档次、技术栈和薪资范围。
- 投递、笔试、技术面、HR 面和终面日期。
- 面试问题和反馈。
- 下一步和跟进日期。

## 异地流程

1. 首选视频技术面。
2. 需要现场终面时集中在 1–2 个工作日。
3. 不因“可能发 offer”提前辞职。
4. 书面 offer 明确岗位、薪资、社保、公积金、试用期和入职时间后再搬迁。

## 面试复盘

- 每次面试当天填写 [面试记录](../../templates/interview-log.md)。
- 24 小时内修复最明显的表达或知识问题。
- 每 10 次投递统计一次简历通过率。
- 每 3 次技术面统计一次高频失败主题。
- 不因为一次失败推翻整个技术主线。

## Offer 检查

- [ ] 岗位实际工作以 Java 开发为主。
- [ ] 试用期薪资和期限明确。
- [ ] 社保、公积金缴纳基数明确。
- [ ] 加班、值班和出差情况明确。
- [ ] 工作地点与搬迁计划一致。
- [ ] 技术栈和团队规模可接受。
- [ ] offer 为书面形式且入职时间明确。
